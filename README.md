# 台股資訊站 — 模組化重構版

這份是你原本 `台股資訊站_第八版_已優化.html`（單一檔案、6300+ 行）依你提供的四大點缺點優化後的版本。
**功能邏輯完全沒變**，只有架構、組織方式、以及幾個確認過的真實 bug 做了調整。

## ⚠️ 部署方式改變了，這件事一定要看

拆成多檔案後改用瀏覽器原生 **ES Modules**（`<script type="module">`），這不需要
webpack / vite 等打包工具，但有一個限制：

**不能直接雙擊 `index.html` 用 `file://` 開啟**，瀏覽器會擋掉模組載入（CORS 限制）。

必須透過本機或正式的 HTTP(S) 伺服器開啟，例如：

```bash
# 方法一：Python（大部分電腦都有）
cd stock-info-v9
python3 -m http.server 8000
# 瀏覽器開 http://localhost:8000

# 方法二：Node.js
npx serve .
```

正式部署到 Cloudflare Pages / GitHub Pages / Netlify 都完全沒問題（它們本來就是用 http(s) 伺服器）。

> 排行榜備援檔案 `rank_fallback.json` 原本就是用相對路徑 `fetch("rank_fallback.json")` 抓的,
> 部署時記得把它跟 `index.html` 放在同一層目錄,跟以前一樣。

## 檔案結構

```
stock-info-v9/
├── index.html              精簡後的 HTML,只剩結構,樣式/邏輯都外部連結
├── css/
│   └── styles.css          原本的 <style> 內容,整份搬出來
└── js/
    ├── config.js            集中管理 API_BASE / TWSE_OPENAPI / TPEX_OPENAPI 等常數
    ├── storage-safe.js       localStorage / window.storage 的安全包裝(含記憶體降級)
    ├── utils.js              兩邊共用的小工具(escapeHtml/debounce/showToast...)
    ├── pagination.js         表格分頁的共用邏輯
    ├── theme-sync.js         讓兩個子應用的深色/淺色主題保持同步
    ├── quote-app.js          股票查詢/首頁/技術分析/排行榜/收藏(原本第一支 <script>)
    ├── aggregator-app.js     資料彙整站(原本第二支 <script>)
    └── main.js               進入點,import 上面兩個 app,並處理共用的設定面板
```

## 對照你列的四大點,實際做了什麼

### 一、架構與程式碼組織
- **單一巨大檔案** → 拆成上面的檔案結構。兩支主要邏輯(quote-app.js / aggregator-app.js)
  因為內部共用大量可變狀態(`currentCode`、`latestDailyRows`、圖表座標換算…),沒有勉強再拆成
  api.js/chart.js/ui.js 這種更細的顆粒度 —— 在沒有測試環境的情況下手動拆分幾千行、
  重新接線所有跨檔案的共用狀態,風險遠大於好處。這是刻意的取捨,不是漏做:
  如果你之後真的想拆到函式等級,建議的做法是先幫這兩支各自補上單元測試,再逐步抽取,
  而不是一次手動搬完。
- **全域變數污染** → 改成 ES module 後,`const`/`let`/`function` 天生只在模組作用域內,
  不需要再手動包 `(function(){...})()`(aggregator-app.js 原本的手動 IIFE 已經拿掉)。
- **截斷/語法錯誤** → 檢查過這份「已優化」版本,你之前提到的截斷字串
  (`已刪除資料夾「${folder.name}」`)其實已經修好了,不是這個版本的問題。

### 二、效能與資料處理
- **大資料表格分頁** → 資料彙整站的主表格(可以顯示到「全部」上千檔股票)加了分頁,
  預設每頁 50 筆(`config.js` 的 `PAGE_SIZE`),排序/搜尋/篩選改變時會自動跳回第一頁。
  排行榜表格原本就有「顯示前 N 名」選項且上限是 50,不算是真的無上限渲染,沒有額外加分頁。
- **搜尋防抖** → 股票查詢的搜尋輸入框、資料彙整站的搜尋框都加了 250ms debounce
  (`config.js` 的 `SEARCH_DEBOUNCE_MS`)。查詢的候選清單本來就有做記憶體快取
  (`buildSearchCandidates` 只在第一次呼叫時建立清單),這部分維持原樣。

### 三、硬編碼與依賴性
- **API 網址寫死** → `config.js` 集中管理預設值,另外在頁面右上角加了「⚙ 設定」面板,
  可以直接貼上你自己的 Worker 網址存起來,兩個子應用共用同一份設定,換 Worker 不用再改原始碼。
- **localStorage/window.storage 不夠強健** → `storage-safe.js` 統一包裝:寫入失敗時
  (空間滿了、無痕模式擋掉)自動降級成記憶體暫存,並跳一次 toast 提示使用者
  (原本資料彙整站的 `window.storage` 呼叫也一併走這層,不再各自處理)。

### 四、UI/UX 與樣式管理
- **CSS 變數作用域混雜** → 這是這次檢查中發現最值得修的一個真實問題:全站 `:root`
  跟資料彙整站的 `#page-aggregate` 各自定義了 `--bg`、`--text`、`--panel`、`--panel-2`、
  `--text-dim`、`--mono` 這 6 個**同名但顏色完全不同**的變數,靠 CSS 選擇器作用域各自生效。
  已經把資料彙整站那組改名成 `--agg-bg`、`--agg-text`…(純改名,顏色數值完全沒變,
  畫面不會有任何視覺差異),消除同名變數在不同區塊代表不同顏色的混淆。
  另外也把唯一一處真的寫死、不會跟著深色/淺色切換的顏色
  (`.quote-table th` 的 Excel 藍 `#4472c4`)抽成 `--table-header-bg` 等 token
  (預設深淺色維持同一個藍,如果之後想讓它跟著主題變,只要改這裡)。
  其餘散落的顏色(漲跌配色、AI 分類標籤的綠/橘/灰)是刻意的品牌色,不是這次要修的 bug,
  沒有動它們。
- **兩個主題開關互不同步(額外發現的 bug)**:原本股票查詢頁的深色/淺色按鈕只切換
  `<body class="theme-light">`,資料彙整站自己的主題按鈕只切換 `<html data-theme="light">`,
  兩者互不相通 —— 按其中一邊,另一個分頁的顏色不會跟著換。新增 `theme-sync.js`
  讓兩邊的切換函式都同時設定這兩個標記,現在按哪一邊都會兩邊一起換。
- **手機巢狀分頁層級過深** → 「財務分析」底下第三層的四個分頁按鈕(月營收/獲利/股利/資產負債),
  在 560px 以下的手機斷點會自動隱藏按鈕列,改成一個 `<select>` 下拉選單,選單跟按鈕列
  共用同一個切換函式,狀態互相同步。桌機/平板維持原本的橫向按鈕列不變。
